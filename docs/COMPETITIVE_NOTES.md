# Competitive notes

Updated 2026-10-10. These are product hypotheses and comparison boundaries, **not measured competitive superiority**. This supersedes earlier shortest-path, mastery-readiness, and market-score positioning. Historical automated audits remain engineering diagnostics, not learning-effect evidence.

## Capabilities that are not exclusive

General GPT/Claude agents can explain papers, generate generic maps and interactive HTML, write notes, ask understanding questions, and organize supplied files. A capable baseline can also implement source links and persistent records when asked. Do not claim that generic maps, summaries, quizzes, local HTML, or an attractive graph establish an exclusive advantage.

[ChatGPT Study Mode](https://help.openai.com/en/articles/11780217-using-study-mode-in-chatgpt) documents guided questions, staged explanations, and understanding checks. [Claude Artifacts](https://claude.com/resources/articles/build-artifacts) documents interactive artifact creation. These official sources support feature overlap, not a claim that either native product cannot perform research handoff or that fields-study-flow is better. Native-product versions, tool settings, and account capabilities must be recorded during any actual comparison.

Source-grounded study aids and literature/navigation products are also relevant references: [NotebookLM](https://notebooklm.google/), [Elicit](https://elicit.com/), [Explainpaper](https://www.explainpaper.com/), [ResearchRabbit](https://www.researchrabbit.ai/), [Litmaps](https://www.litmaps.com/), [PaperQA](https://github.com/Future-House/paper-qa), and [roadmap.sh](https://roadmap.sh/). These links identify comparison candidates; their current limitations, quality, prices, and performance have **not** been established here. Do not turn a missing feature in a historical scan into a current exclusion claim. [React Flow](https://reactflow.dev/) is interface infrastructure, not a competing tutoring product or proof of effectiveness.

## Added value to test

| Workflow hypothesis | What the workbench organizes | Required proof / possible failure |
| --- | --- | --- |
| Persistent cross-material anchors | Paper/paragraph, code symbol/lines, configuration keys, existing result locations in one versioned context. | Reviewer can follow the exact supplied material. Wrong associations, stale anchors, absent files, or path failures count against the hypothesis. |
| Honest material gaps | Explicit missing method, implementation, config, or result; candidate relations remain unreviewed. | User notices unsupported conclusions. A plausible invented explanation or generated scaffold mistaken for evidence is a failure. |
| Goal-directed reading and handoff | Understand/present/extend steps connected to source questions and portable personal records. | Independent explanation, source-linked presentation, or valid modification entry. A checkbox or model score alone earns no understanding credit. |
| Recheckable continuity | Stable IDs, fingerprints, affected-answer recheck, report and companion local files moved together. | Another researcher can inspect the handoff after relocation/change. Export existence alone is insufficient. |

The B three-column interface supports this workflow: steps left, map/paragraph reading center, explanation/source context right. Its usability must be checked on actual exported HTML, not inferred from a development view, static marker count, or screenshot-proxy score.

## Fair comparison and evidence status

Use the [8-12-person protocol](evaluation/research-understanding-protocol.md): a strong direct-agent baseline with the **same model version, materials, tools, generation/request/token budget**, matched goals, different counterbalanced learning materials, independent assessment, and retained failures. Count setup, generation waiting, actual learning time, total time, and costs separately. Native GPT/Claude product comparisons are a separate study, not pooled with same-model results. A baseline may use generic maps, HTML, source citations, and iterative correction.

Public engineering scenarios: [planning-paper, transformer-paper-project, diffusion-missing-materials](../examples/research-workbench/README.md). They use versioned original links and short authored paraphrases, not redistributed full papers. Transformer code/config/expected traces are **our own toy demonstration, NOT actual paper reproduction**. Diffusion deliberately omits method and project evidence. The generator is local/offline and does not execute projects or call remote APIs/external models.

| Evidence | Status |

| Actual HTML / desktop-mobile screenshots / interactions | Generate and inspect final exported bytes; main owns frontend rebuild and capture. No placeholder captures. |
| Recruitment and all human learning/cost/time outcomes | Pending. |
| Comparative benefit or overall superiority | Not established. |

## Contributor entry points

Submit a parsing adapter with a fixture and coverage boundary; a source-backed explanation correction; a licensed case with incomplete-material behavior; or a reproducible UI problem with actual captures. Report input version/hash, environment, actual/expected behavior, failure reason, and sanitized evidence. Preserve negative cases instead of optimizing only the showcase. Do not infer correctness or mastery from anchor presence, model output, or an artifact checklist.
