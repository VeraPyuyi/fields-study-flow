# fields-study-flow 研究理解与接手定位

更新日期：2026-10-10。本文替代此前“最短掌握路径”“就绪分数证明掌握”的推广表达。产品定位是待验证的价值假设，不是已证明的市场优势。

## 首批用户与完整流程

首批用户是需要理解自己或 Agent 生成的论文及核心项目材料、随后汇报或继续修改的研究者。默认只需目标和用户明确指定的文件；已有背景、深度、语言和模型参数按需提供。

1. 提供单篇论文及可用的 README、核心代码、配置、已有结果；选择看懂、汇报或接手修改。
2. 在 B 三栏工作台中查看左侧必要步骤、中间论文逻辑图或段落、右侧解释与来源。
3. 从当前论点定位原文或自有笔记、实现符号/行、配置键和已有结果；缺失材料保留缺口，自动关联保持待核对。
4. 用自己的话回答问题，留下出处和待检查项。导出个人记录与包含资料包的报告，交给下一位研究者。
5. 来源变化后重新核对受影响的定位和回答；生成成功、自我勾选和模型反馈都不能自动授予“完全掌握”。

输入仅静态分析，不执行陌生项目，不重跑实验。现有领域/课程和论文集合入口保留，但本轮新增研究接手语义限于单篇论文。解析支持范围、扫描限额、缺页和格式问题应在报告中保留，不能用解释模板掩盖。

## 增值假设而非独占能力

GPT/Claude Agent 也能生成通用图谱、摘要、逐步解释、测验和 HTML，也可能按要求建立来源记录。不能把这些能力宣传为本项目独有。[ChatGPT Study Mode](https://help.openai.com/en/articles/11780217-using-study-mode-in-chatgpt) 已描述引导学习与理解检查，[Claude Artifacts](https://claude.com/resources/articles/build-artifacts) 已描述交互产物生成。

需要检验的是持续保留的**跨材料锚点、显式证据缺口、可重新核对的研究交接**：材料指纹和稳定 ID 是否减少重新查找；论文/代码关系是否方便人工复核；受影响回答是否得到重检；下一位研究者是否能继续工作。这些是维护一致流程的产品选择，不证明通用 Agent 做不到，也不证明本项目更快。

定位有效只说明材料可定位，located 只说明所引材料已找到；都不等于结论科学正确。自动实验骨架是待做任务，不是已有实现或完成复现。自有教学小例子和手算预期值不能冒充论文实验。

## 模型与费用边界

默认可用 local，auto 未显式启用时仍本地。外部模型必须配置 `FIELDS_STUDY_FLOW_LLM_ENABLED=true`、`FIELDS_STUDY_FLOW_LLM_BASE_URL`、`FIELDS_STUDY_FLOW_LLM_MODEL`、`FIELDS_STUDY_FLOW_LLM_API_KEY`。发现其他密钥不构成上传许可；端点由用户选择，费用与数据政策由其决定。`--offline` 关闭所有生成期网络，`--no-live-search` 只关闭资料发现。

模型只在生成期参与，普通重导出和阅读 HTML 不再调用解释模型。通过来源校验的解释默认缓存在私有 `Path.home() / ".cache" / "fields-study-flow" / "explanations"`，不复制进报告；local/offline 不访问模型或缓存。显式双语生成在缓存命中前进行两次有界语言调用。应把首次生成等待、模型费用、缓存复用和实际学习时间分别计入比较，不能把预生成报告当作零成本。来源检查不能替代解释质量复核或证明掌握。

[生成器和许可/来源记录](../examples/research-workbench/README.md) 不调用远程 API 或外部 LLM、不执行项目代码。实际 HTML、桌面/移动截图和交互记录由主集成流程在最终前端构建后生成并检查。没有截图时注明待生成，不使用占位图作为证据。演示成功与自动化检查仅说明对应工程行为，不证明真实用户学得更好。

按[8-12 人探索性试用协议](evaluation/research-understanding-protocol.md)招募目标研究者，用相同模型版本、相同材料访问权限与工具/调用/令牌预算的强基线；交叉安排不同但近似难度的材料，尽量盲评独立回答，保留未完成、放弃、错锚点、错误解释及缺材料案例。原生 GPT/Claude 产品比较另列，不混成同模型结果。

**当前状态：**招募、试用、评分、失败案例、时间/成本数据和效果提升均待执行。不得填写虚构参与者或结果，不预设宣传百分比。发布前先确保完整流程可用、受测场景无未解决阻断问题；只有实际证据支持时才表达速度、学习或成本提升，并注明条件。

## 开源协作入口

可认领：带 fixture 与覆盖范围的解析适配、附版本化出处的解释修正、许可清晰且含缺口的跨领域案例、可复现的桌面/移动界面问题。提交来源版本/hash、环境、实际/预期行为、真实截图或失败记录，避免上传私有路径和个人回答。核心方向是减少研究交接中的失真和重复核对，而非扩大没有证据的就绪分数。
